### Orchestration settings (app-wide defaults + per-session overrides)

**Built 2026-08-01.** A typed, layered configuration family (`AgentSmithKit/Configuration/OrchestrationSettings.swift`) modeled on the model-override system: system facts + sparse override → resolved value. It governs the OFF behaviors below.

- **`OrchestrationSettings`** is the complete/resolved value (Summarizer, five-point Retrieval, Validator, Security switches). **`OrchestrationSettingsOverride`** is the sparse all-optional delta; `nil` = inherit. `settings.applying(override)` is the ONE merge. Everything defaults ON in `.builtIn` except the retrieval matrix (per-point historical defaults; validator-review memory is OFF because injecting memories would make a verdict depend on the live corpus, which the validator audit hash doesn't cover).
- **Four layers, resolved left→right:** shipped (bundled `Resources/orchestration_defaults.json`, falls back to `.builtIn`) → downloaded (a complete replacement file, `orchestration_defaults_downloaded.json`; download feature deferred, slot wired) → app-wide user override (sparse, `orchestration_settings_override.json`, edited in the **Orchestration** Settings tab, Reset-to-defaults) → per-session override (`SessionState.orchestrationOverride`, edited from **Session ▸ Orchestration Overrides**). `SharedAppState.effectiveOrchestrationDefault` = system.applying(appOverride); `AppViewModel.resolvedOrchestrationSettings` = that.applying(session).
- **UI** reuses the model-override `OverrideTriStateRow` (Inherit / Force-on / Force-off); the tab and the per-session sheet share one form via `OrchestrationOverrideTarget` (app-wide vs session). The sheet shows the resolved value per row.
- **The engine reads a pushed snapshot: `OrchestrationRuntime.orchestrationSettings`** (`private(set)`, default `.builtIn`), set via `setOrchestrationSettings` and refreshed live — app-wide changes fan out to every running session (an observer registered at `start()`), a session's own override is pushed by `orchestrationOverride.didSet`. The runtime never loads files.
- **The guiding rule (user, 2026-08-01): NEVER change the architecture of WHAT gets called; add flags that change IN-CALL behavior.** Every subsystem is still invoked exactly as before; it reads its resolved switch first and either does its normal work or takes a disabled branch that reports it did so. OFF behaviors:
  - **Summarizer** — `summarizeAndEmbedTask` skips the write; `compactSmithContext` (+ `autoCompactSmithIfNeeded`) skip the LLM (the deterministic run-loop prune, `pruneNonBrownHistory`, remains the reduction path).
  - **Validators** — `performTaskValidation` completes the task via `completeValidatedTask(validationWasRun: false)` (banner `validationSkipped`, Smith told criteria were NOT judged), checked before the missing-model park.
  - **Scoping** — `scopeToolSetOnTaskStart` REPLACED the retired `preflightScopingEnabled` (deleted, not reused); read at the spawn gate + propagated to workers from `setOrchestrationSettings`. `setToolSecurity` is now `globalPolicy`-only.
  - **Per-emitter tool-call review** — see the Security Agent chokepoint convention in `docs/claude/reliability-conventions.md`; approves without a verdict but stays visible (`wasEvaluated == false`).
  - **Retrieval** — one entry point `retrieveContext(source: RetrievalSource, query:)` at all five points; the resolved `RetrievalToggle` maps to pool limits (0 = corpus off, both-off = cheap no-op). Exposed to agents/tools via `ToolContext.retrieveContext` and to `SecurityEvaluator` via an injected closure. `SemanticSearchResults.formattedForInjection()` renders the injected block everywhere.
